## GPT Forward Pass

In [the GPT code](../src/model/gpt.py), `B` is batch size, `T` is sequence
length, `C` is embedding size, and `V` is vocabulary size.

```text
token IDs [B, T]
    -> token embeddings + learned position embeddings [B, T, C]
    -> stacked Transformer blocks [B, T, C]
    -> final LayerNorm [B, T, C]
    -> vocabulary head [B, T, V]
```

Each [block](../src/model/block.py) does:

```text
x = x + causal_multihead_attention(LayerNorm(x))
x = x + MLP(LayerNorm(x))
```

The additions are the residual connections. Attention uses separate Q, K, and V
projections, splits them into heads, and masks future tokens before softmax.
The score tensor has shape `[B, H, T, T]`, where `H` is the number of heads.

[LayerNorm and the MLP](../src/model/layers.py) are simple implementations.
The MLP expands the embedding, applies GELU, and projects back down.
The output head has separate weights from the token embeddings.
Attention defines a dropout module, but does not use it, so the GPT has no active dropout.

With targets, the model returns `(logits, loss)`. It flattens the prediction
positions for cross-entropy. Without targets, it returns logits.
Inputs must fit the position-embedding table; generation keeps the latest context window.

## Tokenizer and Data

BPE starts with the 256 possible bytes. Training counts adjacent pairs and merges
the most common pair repeatedly. The encoder uses a heap to pick the next merge
by its learned priority, updating nearby pairs after each merge.

The saved tokenizer contains byte values, merge rules, a version, and an
end-of-document token (EOD). Old tokenizer files still load without changing IDs,
but new dataset preparation needs EOD and the configured vocabulary size.

Decoding encoded text should recover the original UTF-8 text. Generated bytes can
be invalid UTF-8, so generation replaces invalid sequences rather than crashing.

Documents are split before tokenization and end with EOD. Training samples windows
from the combined binary stream, so a window can cross document boundaries.
There is no separate attention mask between documents.
See [data preparation](training.md#dataset-preparation).

## Training and Generation

[Training](../src/train.py) connects data loading, GPT, AdamW, accumulation,
scheduling, validation, and checkpoints. BF16 and `torch.compile` are optional;
the current configs disable them. There is no distributed training or FP16 scaler.

[Generation](../src/generate.py) reads the model shape from the checkpoint and
checks that the tokenizer matches. It generates one token at a time and stops
at EOD or the length limit. Temperature zero picks the highest-scoring token;
positive temperature samples from softmax. There is no KV cache, beam search,
top-k/top-p sampling, or chat format.

[The showcase](../src/model_showcase.py) runs ten GPU generation commands and saves
their output and errors. The prompt labels are things to try, not claims about
what the model can do.
